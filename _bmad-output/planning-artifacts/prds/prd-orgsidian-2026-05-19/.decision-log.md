## 2026-05-19 — Decision: narrow positioning from brainstorming

**Conflict.** Brainstorming Phase 1 framed the open wedge as "Task & Project Planner Powered by Org-mode" against a niche described as "non-saturated." Research found the planner+PKM niche is presidiated: NotePlan (Apple-only, planner-first, plain-text notes) and Obsidian+plugins (notes-first, planner via plugins like Project Planner) both occupy it. Niche is not unsaturated as-stated.

**Decision.** Reframe positioning in PRD §1 Vision: the open wedge is the *specific combination* — desktop-native + cross-platform + OSS + `.org`-native + planner-framed. Drop the "non-saturated planner+PKM" framing; replace with "the unification is the differentiator, scoped to a niche no incumbent fully covers."

**Surfaces in.** PRD §1 Vision (paragraph 3). PRD §10 OQ — no new question; this is a resolved framing decision. Brainstorming §Phase 1 + §Phase 3 Candidate A remain valid as product-reasoning; the marketing framing tightens.

## 2026-05-19 — Decision: parser license is a critical decision, not a detail

**Conflict.** Brainstorming Phase 3 surfaced "don't write the parser, use uniorg or tree-sitter-org" as Decision architettura #3, without analyzing license consequences. Research found uniorg is GPL-3.0-or-later (contagious copyleft); tree-sitter-org is MIT but incomplete on inline markup and TODO semantics.

**Decision.** Elevate parser/license choice to OQ-1 in PRD §10 and to addendum §A.2 with full options matrix. Adopt either: (a) uniorg + accept GPL-3.0 for Orgsidian, or (b) tree-sitter-org + custom semantic layer + permissive license. Both viable; Spike 1 (Months 1-2) resolves. Stack choice (Tauri vs. Electron) is coupled to parser choice — decide together.

**Surfaces in.** PRD §4.1 FR-5 Notes, §7.3 Cost (license ASSUMPTION), §10 OQ-1 and OQ-8, §12 Assumptions Index. Addendum §A.2 carries full analysis.

## 2026-05-19 — Decision: target audience is "org-curious non-Emacs users," not "knowledge workers"

**Conflict.** Brainstorming Phase 2 set target as "knowledge worker generico, freelancer come persona faro." Research found the org-mode community is Emacs-loyalist and culturally skeptical of non-Emacs org tools (Karl Voit's 2024 post on Logseq's lossy org dialect is the canonical critique-frame). The realistic primary addressable audience is the diaspora — org-curious users who bounced off Emacs and Logseq-org users displaced by the DB-version transition.

**Decision.** Tighten §2 Target User with explicit Non-Users (v1) section naming Emacs power users as deliberately out-of-scope. Add §A.6 in addendum sizing the realistic audience at 5,000-20,000 globally for the primary addressable. Update launch-comms guidance: target diaspora, not loyalists; lead with "fidelity + access," not "we improved on Emacs."

**Surfaces in.** PRD §1 Vision (paragraph 3 "this is not a play for the Emacs-loyalist community"). PRD §2.1 Persona. PRD §2.3 Non-Users (v1). PRD §11 SM-C3 (counter-metric on Emacs-user conversion). Addendum §A.6.

## 2026-05-19 — Decision: PRD body describes v1.0 as target product; MVP = v0.1 Alpha

**Issue.** Brainstorming sets a 3-milestone roadmap (v0.1 Alpha → v0.5 Beta → v1.0) over 18 months. The PRD must define "MVP scope" — but the natural interpretation could be either: (a) MVP = v0.1 Alpha (first public release, validates fidelity); (b) MVP = v1.0 (target product, validates positioning).

**Decision.** PRD body describes the v1.0 target product in §4 Features. §6 MVP Scope explicitly defines v0.1 Alpha as the MVP, with v0.5 Beta and v1.0 as named successive milestones in the same scope section. This gives the contributor audience the full v1.0 picture while the dev-anchor audience gets the explicit "v0.1 Alpha is the first ship" focus. Rationale: a v0.1-only PRD body would underspecify the v1.0 product the architecture must be designed for.

**Surfaces in.** PRD §4 preamble (all FRs describe v1.0 unless tagged otherwise). PRD §6.1, §6.2, §6.3 — three named milestone scopes. PRD §11 SM-1, SM-2, SM-3 — one success criterion per milestone.
