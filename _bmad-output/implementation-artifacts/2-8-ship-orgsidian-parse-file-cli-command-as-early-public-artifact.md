## Story

As an **early adopter curious about Orgsidian's parser**,
I want `orgsidian parse <file> [--json]` printing the parsed AST,
So that I can test Orgsidian's fidelity on my own `.org` files before any GUI ships (light-touch John P1 — early public signal at month ~4 instead of month 6).

**Traces:** LD-27 (CLI command tree — first command of the tree), FR-1/FR-2 (exercised, not owned — trace headers stay with `orgsidian-parser`), architecture "CLI Documentation Strategy" (clap annotations as primary docs + `clap_mangen` man pages), architecture Crate Dependency Graph + deny.toml LEAF rule (CLI consumes `orgsidian-core` only).

## Scope Fence (read first)

This is the **first real CLI command** story: `orgsidian parse <file> [--json]`, the façade wiring it needs, its tests, and its man page. It is **not**:

- **NOT the rest of the LD-27 command tree.** No `index`, `query`, `validate-plugin`, `vault` subcommands — only `parse`. Structure the clap derive so future subcommands slot in (a `Command` enum with one variant today), but do not stub unimplemented subcommands.
- **NOT a parser change.** `parse()`, `analyze()`, `serialize()`/`serialize_document()` behavior is frozen. The ONLY permitted `orgsidian-parser` edits are additive serde `Serialize` derives behind a new opt-in `serde` cargo feature (AC2) + the feature plumbing in its `Cargo.toml`. Sentinels stay byte-untouched: `tests/anchor.rs`, `tests/grammar.rs`, `tests/semantic.rs`, `tests/round_trip.rs`, `tests/fixtures/**`, `build.rs`, `src/grammar/`, `grammar/` (LD-48), `src/serializer.rs`.
- **NOT Story 2.5/2.6/2.7 turf — a concurrent pipeline is implementing Story 2.5 right now.** Do not touch `tools/`, root `fixtures/`, `.github/workflows/*`, git-LFS config, or `docs/adr/`. The CLI test fixture is **co-located** at `crates/orgsidian-cli/tests/fixtures/` per the CONTRIBUTING fixture-placement rule (root `fixtures/` is only for ≥2-crate consumers — and it is 2.5's deliverable).
- **NOT `docs/cli.md`.** The architecture's CLI Documentation Strategy names a Markdown reference regenerated by the build step; the epic AC requires only the man page. Defer `docs/cli.md` (record in deferred-work) — `--help` is the user manual for now.
- **NOT stdout-format stability contracts.** Human-readable output is best-effort presentation; the JSON shape is "current semantic `Document`, serde-derived" with NO schema-stability promise yet (the IPC/specta camelCase surface in Epic 4+ is the eventual contract). Document this in the command's `long_about`.

The deliverable is exactly: workspace + `orgsidian-core` façade wiring (AC1), feature-gated `Serialize` on the semantic types (AC2), the `parse` subcommand with human-readable and `--json` output (AC3/AC4), build-time man page (AC5), `assert_cmd` integration tests (AC6), green gates (AC7), deferred-work hygiene (AC8).

**Then**:

## Dev Notes

### 1. The LEAF graph rule is a hard gate, not a convention (do not relitigate)

`deny.toml:162-196` declares `wrappers = ["orgsidian-core"]` for every leaf including `orgsidian-parser` — `cargo deny check bans` (CI per-PR) **fails** on a direct `orgsidian-cli → orgsidian-parser` edge. The epic AC text ("the CLI command is added to `crates/orgsidian-cli/` via clap derive") is silent about this; the architecture is not (Crate Dependency Graph: "Consumers … consume `orgsidian-core` only — never reach into leaves directly"). Hence AC1's three-manifest wiring. This story creates the **first** `core → parser` edge — the architecture-anticipated wiring order (architecture.md:654: "`orgsidian-cli` first commands … establishes integration-test surface"; :667: "the CLI is the primary integration-test fixture … any new core feature should have a CLI command exercising it").

### 2. Why a cargo feature for serde, and why Serialize-only

- The parser is a leaf consumed (eventually) by everything; baking serde in unconditionally taxes every future consumer build. `serde = ["dep:serde", "chrono/serde"]` keeps the leaf clean and lets `orgsidian-core` opt in once via the workspace entry's `features = ["serde"]` (feature unification does the rest — the CLI inherits serialization through the façade without naming the feature).
- `chrono/serde` is required: the workspace chrono pin is `default-features = false, features = ["std"]` — `NaiveDate`/`NaiveTime` have no serde impls without it. Zero new crates from this (serde already in-tree); the chrono feature flip is Cargo.lock-visible but version-neutral.
- Serialize-only mirrors `OrgError` (Story 1.4) and avoids the `#[serde(tag)]`-asymmetry trap noted in deferred-work (story-1.4 stanza). Nobody deserializes a `Document` from JSON today; do not invent that contract.
- camelCase `rename_all` aligns CLI JSON with the project-wide wire convention (architecture IPC boundary; Story 1.4's "project-wide camelCase rename" precedent) so Epic 4+ IPC output of the same types won't diverge from what early adopters scripted against.

### 3. build.rs ↔ cli.rs sharing pattern (the one clap_mangen trap)

`build.rs` cannot `use orgsidian_cli::…` (the crate isn't built yet). The standard pattern: keep `src/cli.rs` dependency-minimal (clap + std only) and `include!("src/cli.rs")` from `build.rs`, with clap (derive) duplicated under `[build-dependencies]`. `clap_mangen 0.3.0` provides `generate_to(cmd, dir)` which emits the root page plus one hyphenated page per subcommand — exactly the epic-named `orgsidian-parse.1`. Resolve the output dir from `env!("CARGO_MANIFEST_DIR")`-equivalent (`std::env::var("CARGO_MANIFEST_DIR")` in build.rs) — never cwd-relative. `build.rs` may `expect()` (it's a build tool, not library code). Note `clap_mangen 0.3.0` requires clap ^4 — satisfied by the 4.6.1 pin.

### 4. Real API surface you are consuming (verified at story-creation)

- `orgsidian_parser::analyze(source: &str) -> Result<Document, ParseError>` — total in practice (LD-41 lenience: every input analyzes `Ok`; both `ParseError` arms are defensive). `Document { headlines: Vec<Headline>, todo_config: TodoConfig, preamble: Option<Preamble>, span: Range<usize> }`.
- `Headline` (src/semantic/headline.rs:36-99): `level: u8`, `todo_state: Option<TodoState>`, `title: String`, `tags: Vec<Tag>`, `scheduled/deadline/closed: Option<Timestamp>`, `properties: HashMap<String, String>` (**unordered — sort before printing**), `drawers: Vec<Drawer>`, `clocks: Vec<ClockEntry>`, `links: Vec<Link>`, `raw: String`, `span`, `children: Vec<Headline>`.
- `serialize_document(&Document) -> String` — byte-identical to the analyzed source (Story 2.4 tiling invariant) — powers the cheap AC6 round-trip cross-check.
- Malformed org never errors: it surfaces as ERROR-region content gap-absorbed into `raw`/preamble. The CLI therefore has no "parse failed" UX for org content — only I/O errors fail.

### 5. Test-surface contracts that protect other stories

- Concurrent Story 2.5 pipeline owns `tools/corpus-extractor/`, root `fixtures/`, git-LFS, `docs/adr/` — zero overlap by construction; if you find yourself editing any of those paths, you have left this story's scope.
- `assert_cmd::Command::cargo_bin("orgsidian")` — the **bin name** (`[[bin]] name = "orgsidian"` already in the stub Cargo.toml), not the crate name `orgsidian-cli`.

No `unwrap()`/`expect()`/`println!`-debugging in committed library/binary code (the renderer's intentional `println!`/`writeln!` output path is the product, not debugging; prefer building a `String` and writing once for testability).
- No `Implements FR-` header in the CLI (single-trace-owner: FR-1 → parser `lib.rs`, FR-2 → `serializer.rs`); cite LD-27 in `main.rs` module docs instead.
