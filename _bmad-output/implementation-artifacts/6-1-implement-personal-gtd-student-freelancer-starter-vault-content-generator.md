## Intent

**Problem:** A first-time user who picks a Starter Vault should see *their
workflow*, not a blank editor or a syntax reference, in the first five
minutes (UJ-3, UJ-4, FR-18). Nothing today generates Starter Vault content:
there is no `starter_vault` module, no Inbox/Project/Journal/Someday
template, and no agenda-bearing content anchored to "today" for Stories 6.3/
6.4's Today and Week Agenda queries to read once they land.

**Approach:** Ship a pure-Rust generator in `orgsidian-core` (the only crate
the LEAF graph rule lets wrap `orgsidian-vault`): [`starter_vault::generate_starter_vault`]
takes a [`StarterVaultKind`], a target folder, and a caller-supplied `today`
(`chrono::NaiveDate`, dependency-injected for determinism — never read from
the wall clock here), and writes each starter's small `.org` file set via the
Story 3.1 `atomic_write` subsystem. Each starter (`personal_gtd.rs`,
`student.rs`) ships four files at the Vault root — `inbox.org` (unprocessed
capture), one project/course file with a `TODO`/`NEXT`/`DONE` mix of Next
Actions whose `SCHEDULED`/`DEADLINE` timestamps span today through the
following week, `journal.org` (a couple of daily-log entries), and
`someday.org` (a bare Someday/Maybe list) — so opening the generated Vault
gives Stories 6.3/6.4 non-empty Today/Week Agenda content to query the moment
those routes land.

**Scope decision (locked 2026-09-05):** ship **Personal GTD + Student**
only. The **Freelancer** starter is **deferred**: its AC requires ≥1 project
with ≥3 milestones, ≥1 clocked task in the LOGBOOK, and ≥1 `id:`/
`[[wiki-link]]` reference between Headlines so the BacklinksPanel (Story 8.7,
not yet built) shows ≥1 backlink on first launch — building that content now
would ship data nothing in the app can display yet. Recorded in
`_bmad-output/implementation-artifacts/deferred-work.md`. The Empty starter
ships in Story 11.1 (v0.5 Beta) per the epic's own note — out of scope here
regardless.

Per this scope decision, the module doc-comment reads
`//! Implements FR-18 (Personal GTD + Student starters; Freelancer + Empty deferred)`
rather than the epic's original full-scope wording (which named Freelancer +
"Empty in Story 11.1").

## Boundaries & Constraints

**Always:**
- `today` is a parameter (`chrono::NaiveDate`), never read from the wall
  clock inside `starter_vault` — mirrors the `test_support::Clock` fake-time
  precedent and keeps every generated byte deterministic in tests. Resolving
  the real first-launch date and wiring the Starter Vault picker UI is Story
  6.2's job, not this story's.
- Files write through `orgsidian_vault::atomic_write` (the established
  Story 3.1 subsystem), mapped to `OrgError` via the existing
  `crate::index::vault_err` helper — no new write path.
- Every generated `.org` file must be independently parseable by
  `orgsidian_parser::analyze` without panicking (LD-41 lenient posture is
  irrelevant here — the point is the generator emits *well-formed* org, not
  content that needs the lenient fallback).
- At least one Headline per starter's project/course file is `SCHEDULED` for
  exactly `today`, and at least one other Headline is `SCHEDULED` within the
  following 7 days — the concrete shape behind "opening the Vault
  immediately shows non-empty Today/Week Agenda content".
- `inbox.org` exists at the Vault root for both starters and carries no
  `SCHEDULED`/`DEADLINE` (Inbox is unprocessed capture by GTD convention).
- Match surrounding module-doc density (`//! Implements FR-xx (...)` first
  line) and the `pub(crate)` / colocated-`#[cfg(test)] mod tests` pattern
  used throughout `orgsidian-core`.
- `chrono` is added as a direct `orgsidian-core` dependency, but it is
  **already in `Cargo.lock`** (transitive via `orgsidian-parser`) — this adds
  a dependency *edge*, zero new crates (verified: `Cargo.lock` diff is a
  single added line under `orgsidian-core`'s existing dependency list).

**Ask First:**
- Any change to the `orgsidian_vault::atomic_write` signature or the
  `VaultError`/`OrgError` mapping (would ripple beyond this story).
- Adding any dependency not already present in `Cargo.lock`.

**Never:**
- No Freelancer generator, no ≥1-backlink content, no Empty starter — all
  three are out of scope (see Scope decision above).
- No Starter Vault picker UI, no Tauri command, no first-launch wiring — that
  is Story 6.2. This story ships the pure-Rust generator only.
- Do NOT touch `sprint-status.yaml`.

## Design Notes

- **Why `today` is a parameter, not `chrono::Local::now()`.** The workspace's `chrono` pin is `default-features = false, features = ["std"]` (parser's original rationale: only `NaiveDate`/`NaiveTime` are needed, not the `clock` feature). Reading the wall clock would need the `clock` feature, which would ripple into the shared `chrono` resolution for no benefit this story needs — the generator's own contract is "given a date, produce content anchored to it", and resolving the *real* current date belongs to Story 6.2 (the first-launch caller), which can decide its own clock-reading strategy independently.
- **Why the two-line `SCHEDULED:`/`DEADLINE:` split doesn't work.** Org's planning line is the *one* line immediately after a headline; a keyword on a second line is ordinary body text, not planning, to the grammar. Confirmed by a failing test during implementation (`deadline_bearer.deadline.is_some()` returned `None`) — fixed by combining onto one line: `SCHEDULED: <...> DEADLINE: <...>`. Both starters' Next-Action-with-deadline Headlines use the combined form.
- **Why `WAITING` is avoided in generated content.** Orgsidian's default `TodoConfig` (`crates/orgsidian-parser/src/semantic/todo.rs`) classifies `WAITING` in the **done** set of the default cycle (`TODO → NEXT → DONE → WAITING → TODO`), which would render a "waiting for" item as visually done-styled — the opposite of the intended semantic. Generated content sticks to `TODO`/`NEXT`/`DONE` only.
- **Flat file layout, no subfolders.** Both starters write directly at the Vault root (`inbox.org`, `projects.org`/`courses.org`, `journal.org`, `someday.org`) rather than nesting under e.g. `projects/`. Keeps the generator's directory-creation surface to just `vault_root` itself and matches the AC's explicit "Inbox file `inbox.org` exists at Vault root" (no ambiguity about which root).
- **`Cargo.lock` impact.** Adding `chrono` as a direct dep of `orgsidian-core` changes exactly one line in `Cargo.lock` (adds `"chrono"` to `orgsidian-core`'s existing `dependencies` array) — verified via `git diff Cargo.lock`. No new crate enters the lockfile.
