## Intent

**Problem:** Epic 4 needs an editor surface, but there is no CodeMirror host and no IPC path to load a file's source. Under React 19 StrictMode the app double-mounts every component (`main.tsx:26`), so a naive `EditorView` created in an effect leaks a detached view on the discarded mount — the exact failure LD-6 + LD-2 warn about.

**Approach:** Build a minimal `Editor` host component that creates its `EditorView` inside a `useEffect` with idempotent cleanup (`return () => view.destroy()`), accepts `ref` as a plain React 19 prop (no `forwardRef`), and loads source text through a new typed `commands.openFile(path)`. Add a small Rust `open_file` command returning the file's UTF-8 content and regenerate the tauri-specta bindings. This story delivers the lifecycle-safe primitive only — decorations, modes, keybindings, and screen integration land in later stories.

## Boundaries & Constraints

**Always:**
- `EditorView` is created in `useEffect` and destroyed in that effect's cleanup; every created view is destroyed exactly once (StrictMode double-mount leaves zero leaked views). A `disposed` guard blocks view creation / state updates when the async load resolves after unmount.
- `ref` is a regular prop (React 19 ref-as-prop) — no `forwardRef`.
- CM6 owns the buffer; its state is never duplicated into Zustand nor persisted apart from the `.org` file. Loaded source is rendered byte-faithful.
- File content reaches the frontend only via the typed `commands.openFile` client (never raw `invoke`, never `@tauri-apps/plugin-fs`).
- Follow conventions: named-export function component, local `interface *Props`, Tailwind classes; Rust command with no `unwrap()/expect()` outside `main()`.

**Ask First:**
- Wiring a general Vitest unit-test job into CI (`.github/workflows/pr.yml`) — no generic `src/**` gate exists today; a separate deliverable.
- Changing the *global* Vitest env off jsdom (this story scopes happy-dom per-file instead).

**Never:**
- Decorations/widgets, syntax highlighting, editor modes (4.2 / 4.3x); mode switcher, keybindings, Emacs mode (4.5–4.7).
- Vault-relative path resolution, file-open UI, dirty-buffer/save wiring, or mounting the editor into a live route/screen — the test is this story's only consumer.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Open existing file | valid path to a readable UTF-8 `.org` file | `openFile` resolves the file's content; `Editor` renders that source text in the CM6 view | N/A |
| StrictMode double-mount | component mounts, cleans up, remounts (dev) | after settle exactly one live `EditorView`; `destroy()` call count equals view-creation count | N/A |
| Unmount before load resolves | `openFile` promise still pending, component unmounts | no `EditorView` created, no state update after unmount, no leaked view | `disposed` guard aborts view creation |
| Missing / unreadable path | path does not exist or permission denied | `openFile` rejects with `OrgError::Io`; component renders empty/error state, no crash | error surfaced, no panic |
| Non-UTF-8 content | file bytes are not valid UTF-8 | `openFile` returns `OrgError::Io`; no partial render, no panic | error surfaced |

- Given the component is unmounted while `openFile` is still pending, when the promise later resolves, then no `EditorView` is created and no post-unmount state update occurs.

## Design Notes

Leak invariant to prove: after a StrictMode mount→cleanup→remount cycle there are zero orphaned `.cm-editor` nodes and `EditorView.prototype.destroy` was called once per view created. If spying on construction is awkward, route view creation through a tiny factory the test can count, or assert `container.querySelector(".cm-editor")` is null after unmount plus `destroy` was called.

Minimal extension set for 4.1: an editable, source-faithful view only (e.g. `EditorView.editable.of(true)` + default keymap from `@codemirror/commands`). No `basicSetup`, no language/highlight — those are 4.2.
