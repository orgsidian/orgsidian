## Story

As the **author / contributor**,
I want `git-cliff` invoked by the `cargo release` pre-release hook to regenerate `CHANGELOG.md` from Conventional Commits per the [LD-54 mapping table](_bmad-output/planning-artifacts/architecture.md#L600-L611), with a second invocation scoped to `crates/orgsidian-plugin-api/**` writing the per-crate `CHANGELOG.md`, plus a CI-runnable smoke that proves the [LD-54 mapping table](CONTRIBUTING.md#L66-L77) is encoded correctly,
So that every release ships an accurate, automation-generated user-facing changelog without manual curation of `feat` / `fix` / `perf` entries, the `cliff.toml` slot reserved at [architecture.md:1415](_bmad-output/planning-artifacts/architecture.md#L1415) is filled, and the stale "lands in Story 1.15 (not yet created)" pointer at [CONTRIBUTING.md:83](CONTRIBUTING.md#L83) is retired.

## Acceptance Criteria

**AC1 — `cliff.toml` at repo root encodes the [LD-54 mapping table](_bmad-output/planning-artifacts/architecture.md#L600-L611) as `[git.commit_parsers]` + a `[changelog.body]` template producing Keep-a-Changelog format with `Added` / `Changed` / `Deprecated` / `Removed` / `Fixed` / `Security` headings.**

- **NET-NEW file** at repo root: `cliff.toml`. Slot reserved at [architecture.md:1415](_bmad-output/planning-artifacts/architecture.md#L1415).
- `[git.commit_parsers]` MUST encode all eight CC→bucket mappings in the LD-54 table verbatim:
  | CC type / footer | bucket | git-cliff parser |
  |---|---|---|
  | `feat` (non-breaking) | `Added` | `{ message = "^feat", group = "Added" }` |
  | `fix` (non-breaking) | `Fixed` | `{ message = "^fix", group = "Fixed" }` |
  | `perf` (non-breaking) | `Changed` | `{ message = "^perf", group = "Changed" }` |
  | `refactor` (only `refactor!` user-visible) | `Changed` | `{ message = "^refactor!", group = "Changed" }` + skip on non-breaking refactor |
  | `revert` | `Changed` | `{ message = "^revert", group = "Changed" }` |
  | `feat!` / `fix!` / `BREAKING CHANGE:` | `Changed` (entry prefixed `⚠ BREAKING:`) | use git-cliff `breaking` flag on commit + template branches on `commit.breaking` |
  | `docs` / `style` / `test` / `build` / `ci` / `chore` (non-breaking) | *(excluded)* | `{ message = "^(docs\|style\|test\|build\|ci\|chore)", skip = true }` |
  | manual `Deprecated` / `Security` entries | preserved | template renders empty headings when no commits match |
- `[changelog.body]` template is a Tera template (git-cliff's templating engine) producing the exact Keep-a-Changelog v1.1.0 shape (header level `##` for version, `###` for bucket). Empty buckets are emitted as `### <Heading>\n` with no body — required by AC6.
- The Unreleased heading rendered is `## [Unreleased]` (matches the existing literal at [CHANGELOG.md:13](CHANGELOG.md#L13)).
- Versioned headings render as `## [{{ version }}] - {{ timestamp | date(format="%Y-%m-%d") }}` matching the Keep-a-Changelog convention in the plugin-api precedent [crates/orgsidian-plugin-api/CHANGELOG.md:12](crates/orgsidian-plugin-api/CHANGELOG.md#L12).
- `[git]` block: `conventional_commits = true`, `filter_unconventional = false` (don't drop CC-malformed commits silently — surface them under a `### Other` group OR fail loud; default = surface, since LD-54 enforces CC upstream so any leakage is a bug), `commit_parsers` as enumerated above, `tag_pattern = "v[0-9]+\\.[0-9]+\\.[0-9]+(-.*)?"` (LD-33 `v*` scheme; pre-release suffixes like `v0.1.0-alpha.1` accepted).
- `[changelog]` block: `header = """..."""` (preamble pointing to keepachangelog.com + SemVer, matching the existing CHANGELOG.md L1-L11 prose so the regenerated file stays drop-in compatible).
- **DO NOT** add `[changelog.footer]` content (no "Generated by …" footer). Per [[feedback_no_co_author_credit]], no tool-credit lines anywhere.
- **DO NOT** enable `[remote.github]` or any remote-API auto-linking in this story — keep cliff.toml hermetic (no network calls in the pre-release hook). PR-link decoration is a follow-up if/when desired; not in scope here.

**AC2 — `release.toml` at repo root configures `cargo release` `[hooks.pre-release]` to invoke `git-cliff --unreleased --tag <version> --prepend CHANGELOG.md` + a second invocation scoped to `crates/orgsidian-plugin-api/**`.**

- **NET-NEW file** at repo root: `release.toml` (cargo-release reads this OR a `[workspace.metadata.release]` block in `Cargo.toml`; the standalone file is cleaner — see §3 below).
- The file MUST set `pre-release-hook` to a command (or array form for proper argv handling) that runs git-cliff twice:
  1. **Root CHANGELOG**: `git-cliff --unreleased --tag {{version}} --prepend CHANGELOG.md` — overwrites the `[Unreleased]` section of the root `CHANGELOG.md` and bumps it to a versioned heading.
  2. **Plugin-api CHANGELOG**: `git-cliff --include-path "crates/orgsidian-plugin-api/**" --unreleased --tag {{version}} --prepend crates/orgsidian-plugin-api/CHANGELOG.md` — scope filtering via `--include-path` (git-cliff flag) restricts commits to those touching the plugin-api crate (LD-33 separate-changelog discipline).
- `cargo-release` substitutes `{{version}}` with the about-to-be-released version (cargo-release templating; same `{{version}}` token used by `pre-release-replacements`).
- Workspace-mode handling: `cargo-release` runs `pre-release-hook` **once per crate** by default in a workspace. To prevent 9× redundant cliff invocations, the hook MUST be configured at the workspace level (in `release.toml`, since per-crate `release.toml` is not the workspace pattern). Setting at workspace level means it runs once with the workspace version context. **Verify** during implementation: `cargo release --dry-run --workspace` shows the hook in the dry-run plan once.
- `consolidate-commits = true` and `shared-version = true` at workspace level (LD-33 says all Rust crates share the app version with tag scheme `v*` during v0.1 → v1.4) — these are cargo-release flags ensuring single release commit + single shared bump.
- `pre-release-replacements`: leave UNSET (the literal `[Unreleased]` heading in CHANGELOG.md is rewritten by git-cliff itself via `--prepend`; no string-replace needed). **DO NOT** add a string-replace fallback "just in case" — it would double-rewrite and corrupt the changelog.
- **DO NOT** set `sign-tag` or `sign-commit` in this story — git signing infrastructure is a separate concern (no project key set up yet); enabling here without keys would fail every release. Defer to a release-workflow story.
- **DO NOT** add `publish = true` for the workspace — `orgsidian-plugin-api` does NOT publish to crates.io until v1.5+ per LD-33; other crates are bin / internal. Per-crate `publish = false` in `Cargo.toml` already exists or is implicit; cargo-release respects it.
- **DO NOT** wire a `release.yml` GitHub workflow in this story — it is referenced at [architecture.md:910](_bmad-output/planning-artifacts/architecture.md#L910) but no story covers it yet (LD-33 wiring is a v0.1 Alpha-prep story, not Story 1.15). Story 1.15 ships the **config** that a future release-workflow story consumes.

**AC5 — A smoke test runs `git-cliff --unreleased` against a fixture branch and asserts bucket placement.**

Assert the resulting file contains BOTH the new `## [v0.0.1]` section AND the preserved `## [0.0.0]` block ⇒ **PASS --prepend preserves manual entries**.

**AC6 — `Deprecated` and `Security` headings remain present-but-empty when no manual entries exist (template allows empty sections).**

- Covered by AC1 (`[changelog.body]` template renders all six Keep-a-Changelog buckets unconditionally) and AC5 assertion 6.
- The rationale for surfacing this as its own AC (epic-spec): manual entries (Deprecated / Security) live in CHANGELOG.md and are inserted BEFORE `cargo release` tags by the maintainer (per [LD-54](_bmad-output/planning-artifacts/architecture.md#L611) "Inserted before `cargo release` tag"). The git-cliff template must NOT collapse empty sections — otherwise the maintainer's "manually add to Security before release" workflow ([architecture.md:530](_bmad-output/planning-artifacts/architecture.md#L530)) has no `### Security` heading to write into.
- The template MUST use a literal-emit pattern (six explicit `### Heading` lines in the Tera template body), NOT a `{% for group in commits | unique(attribute="group") %}` loop that only emits headings for groups with commits.

1. **Trigger surface divergence**: `release-smoke.yml` needs `push: branches: [main]` (post-merge re-assert) on top of `pull_request`. `pr.yml` already has `push: main` for the matrix but conflating concerns would re-run the entire 30-min matrix when only the 30-second cliff smoke needs to fire.
2. **Tool-install isolation**: `release-smoke.yml` installs `git-cliff` (~5-10s via taiki-e/install-action). Folding into pr.yml adds this to every PR's longest cell (~1m28s on macos-14) for no parallelism gain.
3. **LD-33 surface visibility**: a dedicated workflow file makes the LD-33 release-tool surface grep-discoverable. Future release-runbook stories add to this same file (e.g., a `release-dry-run` job exercising `cargo release --dry-run` once cargo-release is installed).
4. **Failure-mode isolation**: a future cliff.toml refactor bug fails only `release-smoke.yml`; pr.yml stays green. Maintainer can `workflow_dispatch` re-run just the release-smoke gate.
5. **Cost**: one extra file (~40 lines) vs ~20 lines added to pr.yml + the cross-concern entanglement.

The same workflow-header documenting style as `commitlint.yml` applies — comment block at the top explaining LD-33/LD-54 lineage, the dedicated-file choice, and the version-pin policy.

### §5 — git-cliff template: literal-emit Tera pattern for AC6 empty-headings invariant

The naive Tera template — iterating `commits | unique(attribute="group")` — emits a heading only when at least one commit lands in that bucket. This BREAKS the LD-54 "manual entries under Deprecated / Security" workflow because the maintainer has nowhere to write the manual entry.

Correct pattern (literal-emit):

```tera
## [{{ version }}]{% if timestamp %} - {{ timestamp | date(format="%Y-%m-%d") }}{% endif %}

### Added
{% for commit in commits | filter(attribute="group", value="Added") -%}
- {% if commit.scope %}**{{ commit.scope }}:** {% endif %}{{ commit.message | upper_first }}{% if commit.id %} ([{{ commit.id | truncate(length=7, end="") }}](https://github.com/orgsidian/orgsidian/commit/{{ commit.id }})){% endif %}
{% endfor %}

### Changed
{% for commit in commits | filter(attribute="group", value="Changed") -%}
- {% if commit.breaking %}⚠ BREAKING: {% endif %}{% if commit.scope %}**{{ commit.scope }}:** {% endif %}{{ commit.message | upper_first }}{% if commit.id %} ([{{ commit.id | truncate(length=7, end="") }}](https://github.com/orgsidian/orgsidian/commit/{{ commit.id }})){% endif %}
{% endfor %}

### Deprecated

### Removed
{% for commit in commits | filter(attribute="group", value="Removed") -%}
- {{ commit.message | upper_first }}
{% endfor %}

### Fixed
{% for commit in commits | filter(attribute="group", value="Fixed") -%}
- {% if commit.scope %}**{{ commit.scope }}:** {% endif %}{{ commit.message | upper_first }}{% if commit.id %} ([{{ commit.id | truncate(length=7, end="") }}](https://github.com/orgsidian/orgsidian/commit/{{ commit.id }})){% endif %}
{% endfor %}

### Security
```

Notes on the template:
- `### Deprecated` + `### Security` are emitted literally with NO loop — they're maintainer-fill slots.
- `### Removed` has a loop because `revert` doesn't map there; the loop is empty until a future manual entry uses a `removed:` footer convention (deferred).
- The commit-id link decoration uses the hardcoded `orgsidian/orgsidian` URL — repository is public per [[project_orgsidian_repo_public_during_pre_alpha]], so links work; no remote-API auto-discovery needed.
- `commit.scope` is emitted as `**scope:**` bold-prefix (matches Keep-a-Changelog community convention).

|---|---|---|
| 1 | feat→Added | `echo "$OUTPUT" \| grep -A 50 "^### Added" \| grep -F "add tree-sitter wrapper"` |
| 2 | fix→Fixed | `echo "$OUTPUT" \| grep -A 50 "^### Fixed" \| grep -F "handle AV-locked retry"` |

| 5 | chore-excluded | `! echo "$OUTPUT" \| grep -F "bump Cargo.lock"` |
| 6 | empty-headings-emitted | `echo "$OUTPUT" \| grep -q "^### Deprecated" && echo "$OUTPUT" \| grep -q "^### Security"` |
| 7 | scoped: plugin-api commit captured | `echo "$SCOPED_OUTPUT" \| grep -F "rename Event variant"` |
| 8 | scoped: non-plugin-api commits excluded | `! echo "$SCOPED_OUTPUT" \| grep -F "add tree-sitter wrapper" && ! echo "$SCOPED_OUTPUT" \| grep -F "handle AV-locked retry" && ! echo "$SCOPED_OUTPUT" \| grep -F "cache FTS5 query plan"` |

Each assertion in the script wraps as:
```bash
if <pattern>; then
  echo "PASS <N>: <description>"
else
  echo "FAIL <N>: <description>"
  echo "--- captured output (first 100 lines) ---"
  echo "$OUTPUT" | head -100
  exit 1
fi
```

Verbose output on failure is essential — without the captured-output dump, a CI log shows only "FAIL 4" with no diagnostic surface.

### §10 — Test strategy

Three layers of confidence in the LD-54 → CHANGELOG generation chain:

1. **Unit-level smoke** (AC5): `scripts/smoke-git-cliff.sh` exercises the cliff.toml template + parsers against a 5-commit fixture with known bucket placement. Fast (<5s incl. tmp git init), deterministic, runnable both locally (with git-cliff installed) and in CI. The 9 assertions are the contract.

2. **Integration-level CI gate** (AC7): `release-smoke.yml` runs the smoke on every PR + post-merge to main. The post-merge run is the regression net — any future cliff.toml edit that breaks an LD-54 bucket placement is caught by the next merge.

3. **End-to-end release runbook** (DEFERRED to a future release-runbook story, likely Story 6.10's v0.1 Alpha publish): `cargo release --workspace 0.1.0` fires the pre-release-hook, git-cliff regenerates both CHANGELOGs, the maintainer manually adds any Deprecated / Security entries, and `cargo release` tags the version. This story does NOT exercise that path.

The test strategy is appropriate to the story's risk profile:
- **Low complexity**: 4 new files (~265 lines total) + 2 file edits (1-line each).
- **Low blast radius**: failure modes are CI-job-fails (loud + obvious); silent false-passes are bounded by the 9 explicit AC5 assertions.
- **High value**: the LD-54 mapping table is fully smoke-tested; every future cliff.toml edit is regression-guarded by the same 9 assertions. The maintainer-fill workflow for `### Deprecated` / `### Security` is verified.

No new Rust crates / tests introduced; the smoke is a shell smoke, not a `cargo test`. The story's AC9 verification matrix is the post-merge gate.
