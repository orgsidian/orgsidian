## Story

As the **author / contributor**,
I want a working `pnpm create tauri-app@latest` scaffold (React 19 + TypeScript + Vite, Tauri 2.x) with bundle identifier `com.orgsidian.app` landed at the repo root,
so that `pnpm tauri dev` launches a Tauri window on macOS-arm64 and Ubuntu-LTS, and the project is ready for the Story 1.2 refactor into a 9-crate Cargo workspace.

Story 1.2 owns that refactor — do NOT prematurely apply it here. ## Dev Notes

### Critical context the dev agent MUST internalize before touching code

**1. The repo root is NOT empty.** Epic-file AC text "Given an empty project root" is a SIMPLIFICATION — the repo already contains pre-existing scaffolding for Conventional Commits enforcement (`package.json`, `.husky/`, `commitlint.config.cjs`, `scripts/sync-epics-to-github.sh`, `pnpm-lock.yaml`, `README.md` with status badges, `_bmad/`, `_bmad-output/`, `.claude/`). The `create-tauri-app` scaffolder refuses to scaffold into a non-empty directory — that is why **Task 2 scaffolds into a scratch temp dir and Task 3 merges**. Do NOT attempt to delete existing files to "make room" for the scaffolder. Do NOT use `--force` or any equivalent flag.

**2. Use `pnpm create tauri-app@latest` (NOT `@2`) for the Tauri 2.x scaffold.** **REVISED 2026-05-19:** Empirically verified that `pnpm create tauri-app@2` (resolves to v2.8.0 today) emits a **Tauri v1** scaffold (`@tauri-apps/api: ^1.2.0`, `tauri.conf.json` v1 schema, identifier `com.tauri.dev`) — incompatible with the architecture-locked Tauri ≥2.10 requirement. The correct invocation is `pnpm create tauri-app@latest` (currently v4.x family), which emits Tauri 2.x with `$schema: https://schema.tauri.app/config/2`. The non-interactive form used in this story is:

   ```bash
   pnpm create tauri-app@latest orgsidian -m pnpm -t react-ts -y
   ```

   When run interactively (without `-y`), the prompt order is:
   1. Project name → `orgsidian`
   2. Identifier → `com.orgsidian.app` (older versions default to `com.{user}.{name}` and emit `com.tizianobasile.orgsidian`; the non-interactive `-y` form omits this prompt and uses the default, which is then patched in Task 4)
   3. Choose which language to use for your frontend → `TypeScript / JavaScript`
   4. Choose your package manager → `pnpm`
   5. Choose your UI template → `React`
   6. Choose your UI flavor → `TypeScript`

   When the prompt is omitted (e.g. `-y`) or the default identifier is accepted, **Task 4** patches `src-tauri/tauri.conf.json` to set `identifier: com.orgsidian.app` and `version: 0.0.0`. The previously cited URL `https://v2.tauri.app/blog/create-tauri-app-version-3-released` is misleading on this point; the `@2`-stream binary in npm today is Tauri v1.

**3. React 19.1.x or later (latest stable 19-line), NOT 18.x.** Architecture LD-1 + §"Locked Stack Versions" pin React to the latest stable 19-line. `pnpm create tauri-app@latest` currently emits `react@^19.1.0` which resolves to 19.2.x; this satisfies the policy. If a future scaffolder emits React 18.x, the dev agent MUST bump `react` and `react-dom` to `^19.1.0` explicitly in `package.json` after merge. React 19 ships `ref` as a regular prop — do NOT use `forwardRef` for any code added in this story (the default `App.tsx` from the scaffold should already be React-19-clean; if it uses `forwardRef`, refactor it).

**4. The 9-crate workspace is NOT in this story.** Story 1.2 owns the refactor from the flat `src-tauri/` + `src/` layout to `crates/orgsidian-{parser,index,watcher,vault,plugin-api,report,core,cli,shell-app}/` + `shell-ui/` at repo root. Story 1.6 owns Lingui. **DO NOT prematurely install any of those in Story 1.1.** The scaffold's emitted dependencies are the ONLY dependencies that should land in `package.json` and `src-tauri/Cargo.toml` from this story. ([Source: architecture.md#First Implementation Stories (preview)](../planning-artifacts/architecture.md), [Source: epics.md Story 1.2/1.3/1.4/1.6](../planning-artifacts/epics.md))
